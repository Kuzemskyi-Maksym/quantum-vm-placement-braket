# Квантове розміщення ВМ — порівняння методів (AWS Braket)

Код для порівняння методів розв'язання задачі розміщення віртуальних машин (VM placement / consolidation),
сформульованої як QUBO/CQM, на спільних тестових інстансах, із запусками QAOA на реальному квантовому
залізі (IQM Garnet) через Amazon Braket. Продовження першої статті (QAOA + SLR).

Супровідні нотатки (контекст, рішення, журнал запусків) — в Obsidian-сховищі, не тут.

## Інстанси (`config.py`, змінна середовища `VMP_INSTANCE`)
| Назва | ВМ | ФС | Призначення |
|---|---|---|---|
| `full` (за замовч.) | `[3,4,2,5,3,4]` | `[12,12,12]` | інстанс першої статті; лише класичні методи (~33 кубіти зі slack) |
| `common` | `[6,5,2,1]` | `[12,12]` | спільний інстанс для всіх 5 методів; 10 кубітів у slack-free кодуванні |
| `W` | `[6,5,2,1]` | `[12,12,12]` | warm start / критерій міграцій; 15 кубітів; поточний розподіл `X0=[0,1,2,2]` |
| `large` | 30 ВМ (seed 7) | 12 × 20 | лише класичні (ГА vs BRKGA) |
| `rand` | `VMP_N` ВМ, `VMP_SEED` | `VMP_N` × 20 | випадкові великі інстанси, лише класичні |

Спільні параметри: поріг утилізації `T = 0.9`, множники штрафу `λ1 = λ2 = 6.0` (slack-free QAOA: `λ = 3`).

### Критерій з міграціями (рішення керівника, 2026-11-01)
Ціль: **F(x) = (активні ФС) + MU · Σ_j s_j·[ВМ j змінила сервер] / Σ_j s_j** — вартість переміщення
пропорційна розміру ВМ; другий член нормовано в [0, 1] (переселити всі ВМ коштує MU). `X0` — поточний
розподіл (`VMP_X0="0,1,2,2"`), `MU` — `VMP_MU` (за замовч. 1.0). Якщо `X0 = None`, F = кількість ФС, як раніше.
Для QUBO член міграцій — лише лінійні поля на кубітах x_{j,X0[j]}: нових кубітів не потрібно.
Реалізовано в `cp_sat.py` (точна ціль), `brkga.py` (фітнес + ключі «залишитись»), `warm_start_qaoa.py`.

## Методи
| Файл | Метод | Примітка |
|---|---|---|
| `mbfd.py` | MBFD (Modified Best Fit Decreasing) | жадібна евристика; міграцій не бачить — baseline «повна переукладка» |
| `cp_sat.py` | CP-SAT (Google OR-Tools) | точний еталон, з ціллю F (ФС + міграції) |
| `brkga.py` | **BRKGA** (Gonçalves & Resende) | основний ГА для порівнянь; декодер First Fit; у режимі міграцій 2N ключів |
| `genetic.py` | базовий ГА | лишено лише для `compare_ga.py` (на 30+ ВМ програє BRKGA) |
| `annealing.py` | SimulatedAnnealingSampler (`dwave-samplers`) | класична емуляція відпалу |
| `qaoa_noslack.py` | QAOA без slack-бітів, точна симуляція | парні штрафи місткості; 8–15 кубітів |
| `qaoa_noslack_noisy.py` | те саме з шумом (Aer, топологія 3×3) | ілюстративні рівні помилок |
| `qaoa_noslack_real_qpu.py` | QAOA на IQM Garnet | режими `local` / `submit p shots` / `fetch <TaskID>` / `control p shots` |
| `warm_start_qaoa.py` | QAOA з теплим стартом із X0 | ціль «максимум P(кращий за x0)», член міграцій MU |
| `qaoa.py`, `qaoa_exact.py`, `qaoa_real_qpu.py`, `qaoa_fetch_result.py`, `qaoa_aer_control.py` | старе slack-кодування (16 кубітів) | лишено для відтворення перших прогонів |

`cqm_model.py` — CQM/BQM (dimod) для slack-кодування.

## Порівняльні скрипти
```powershell
python run_all.py                                              # 5 методів на full → results.json
$env:VMP_INSTANCE="common"; python compare_common.py           # 5 методів на common (ГА = BRKGA) → results_common.json
$env:VMP_INSTANCE="large";  python compare_ga.py               # базовий ГА vs BRKGA на великих інстансах
$env:VMP_INSTANCE="W";      python compare_migration.py        # ціль з міграціями, MU ∈ {0,0.5,1,2,5} → results_migration.json
$env:VMP_INSTANCE="W";      python warm_start_qaoa.py pbetter --mu 1
$env:QAOA_INSTANCE="C";     python qaoa_noslack_real_qpu.py submit 2 1000   # платний запуск на Garnet
```
У `compare_migration.py` точний оптимум рахується ще й повним перебором (M^N розподілів), тому скрипт
працює і без OR-Tools.

## Встановлення
```bash
pip install dimod dwave-samplers ortools qiskit qiskit-aer scipy numpy
```
Для запусків на Braket додатково `pip install amazon-braket-sdk boto3` і налаштований `aws configure`.

## Результати (коротко)
- **Класичні методи** (CP-SAT, MBFD, BRKGA, відпал) на `full` і `common` знаходять оптимум; BRKGA — оптимум у
  всіх запусках і на 30–60 ВМ, де базовий ГА провалюється, а MBFD помиляється на 1 сервер.
- **Slack-free QAOA на IQM Garnet:** інстанс B (8 кубітів, p=2, 1000 shots) — 20.9% ± 1.3% оптимальних shots
  проти 1.6% випадково; контроль із випадковими кутами 1.9%. Інстанс C (10 кубітів) — 7.3% ± 0.8% проти 0.78%.
  Результати узгоджуються з шумною симуляцією при ефективній помилці CX ≈ 1–2%.
- **Warm-start QAOA (точна симуляція, інстанс W):** p=2 дає ≈6% shots, кращих за x0; класичний випадковий сусід
  на 1–2 міграції — 25–40%. На малому інстансі квантовий варіант не виграє (див. `results_migration.json`).
- Застереження: інстанси іграшкові (8–15 кубітів); перевага квантового методу над класикою не заявляється.
  Рамка — здійсненність на NISQ-залізі та вплив шуму.

**Старе slack-кодування** (`qaoa.py`, 16 кубітів) не концентрує розподіл на допустимих розв'язках
(11.9% допустимих при baseline 12.5%); «QAOA знайшов оптимум» у ранніх звітах був артефактом відбору з тисяч
shots. Виправлено переходом на slack-free кодування.
